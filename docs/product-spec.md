# Threads Public Monitor 產品規格

## 目標與範圍

`threads-public-monitor` 是部署於單台 Ubuntu 主機、透過 Tailscale 私網使用的繁體中文內部工具。系統使用專用 Threads 擷取身分，定期觀察最多 16 個任意公開帳號，保存個人檔案、統計數字、公開內容與媒體的歷史變化。

系統不擷取私人帳號，不把擷取身分自身的個人內容納入資料，不實作應用程式登入，也不直接對公開網際網路開放。

## 新增與管理監看帳號

- 首頁接受 `https://www.threads.com/@sin_9311`、`@sin_9311` 或 `sin_9311`。
- 輸入值正規化為小寫的標準使用者名稱；同名帳號不得重複。
- 新增後先建立待驗證卡片，由背景 Worker 按節流規則確認帳號存在且公開。
- 不存在、私人或暫時無法讀取時，在卡片顯示原因，不阻塞首頁。
- 已停止監看的同名帳號再次加入時，恢復原帳號與既有歷史。
- 最多同時啟用 16 個監看帳號。
- 一般移除採「停止監看」：停止排程、移出首頁，但保留全部資料。
- 詳情頁另提供二次確認的「永久刪除」；只有不再被任何內容引用的媒體實體檔案才會一併刪除。

## 排程、分批與風控

- 每個帳號可選 6、12 或 24 小時拜訪週期，預設 12 小時。
- 名義週期到期後隨機延後 0–30 分鐘，不提前執行。
- 全系統只有一個擷取批次可同時執行。
- 批次之間隨機等待 3–8 分鐘，每日最多執行 200 個批次。
- 每批最多處理 10 筆公開內容，保存續抓位置後再由後續批次接續。
- 初始回補針對串文、回覆、轉發與引用轉發，各自最多取得最近 100 筆；公開可見內容不足時，以實際可取得數量為準。
- 初始回補允許跨數天完成，完成後轉為增量擷取。
- 單次失敗採指數退避；同一帳號連續失敗 3 次後進入 24 小時擷取冷卻，期滿自動恢復。
- 首頁顯示失敗原因、冷卻狀態與下次重試時間。
- 「立即重試」仍必須通過全域節流，不得繞過佇列或冷卻保護。
- 遇到驗證頁、限制頁或無法辨識的頁面時停止該次擷取，不嘗試繞過。

## 專用 Threads 擷取身分

- 使用專用 Threads 帳號的持久化 Chromium 工作階段擷取公開帳號。
- 應用程式與資料庫不接收或保存 Threads 帳號密碼。
- 首次登入或工作階段失效時，按需啟動只綁定 Tailscale IP 的互動式 `browser-login` 服務。
- 操作者在私網瀏覽器畫面中親自輸入帳密與驗證碼；登入完成後停止該服務。
- 登入工作階段存放在權限受限的 Docker 掛載目錄，供唯一的背景 Worker 使用。
- 工作階段失效時暫停擷取，首頁顯示需要重新登入。

## 個人檔案與統計資料

- 保存使用者名稱、顯示名稱、簡介、公開連結、頭像、粉絲數與追蹤數。
- 顯示名稱、簡介、連結或頭像發生變化時建立新的個人檔案版本，保留首次與最後觀察時間。
- 每次成功拜訪建立粉絲數與追蹤數統計快照。
- 粉絲與追蹤中名單各自每日最多建立一輪掃描，每批最多保存 5 個可見帳號及其頭像。
- 名單顯示已擷取數量與掃描狀態，不將部分名單宣稱為完整名單。
- 首次完整掃描建立基準；後續完整掃描才列出新增與退出。未完成掃描不判定退出。
- Threads 未顯示或解析器無法確認的欄位保存為未知，不得寫成 0。

## 公開內容模型

- 一筆公開內容的主類型只能是串文、回覆、轉發或引用轉發。
- 照片與影片是內容特徵，不是另一種主類型；影音頁只是含媒體內容的篩選檢視。
- 同一筆內容只保存一份，可同時出現在主類型頁與影音篩選結果。
- 保存 Threads 內容識別碼、作者、建立時間、文字、引用／回覆關係、來源網址、主類型與附件關係。
- 文字或附件改變時新增內容版本，不覆蓋舊值。
- 內容暫時未出現在列表中不視為刪除；只有直接網址在三次不同拜訪中皆不可用，才標記為「疑似已移除」。
- 疑似已移除的原文、版本與本機媒體仍然保留。
- 按讚、回覆、轉發及分享數只在正常擷取流程再次看見內容且數值改變時建立互動快照，不額外巡覽舊內容。
- 未顯示的互動數字保存為未知，不得當成 0。

## 媒體保存與容量

- 頭像、貼文照片與完整影片都下載至 Docker 掛載的主機媒體目錄。
- 下載前以來源識別資訊快速判重；下載後以內容雜湊做最終去重。
- 相同媒體不論由多少內容或網址引用，都只保存一份實體檔案。
- 單一媒體檔上限 500 MB；超過時保存來源資訊與未下載原因。
- 媒體容量上限 100 GB；達 80% 時在首頁警示，達 95% 時停止下載新媒體，但繼續保存文字與統計資料。
- 系統不做每日備份，也不在同一主機重複備份媒體。
- 每次版本更新前建立 SQLite 一致性備份，供更新失敗時回復。

## 使用者介面

- 介面固定使用繁體中文與深色主題，日期及數字依台灣格式顯示。
- 首頁為響應式卡片網格：桌面多欄、手機單欄。
- 卡片可由專用拖曳把手排序，支援滑鼠與觸控；排序持久保存，與擷取優先級無關。
- 卡片顯示頭像、顯示名稱、`@使用者名稱`、粉絲數、追蹤數、相較前次的增減、最後成功擷取時間、下次預定時間、狀態與初始回補進度。
- 卡片提供立即重試、停止監看與進入詳情；永久刪除只出現在詳情頁危險操作區。
- 詳情頁頁首顯示個人檔案、粉絲／追蹤數趨勢與媒體保存狀態。
- 詳情頁包含「全部、串文、回覆、轉發、引用轉發、影音、粉絲名單、追蹤中、每日差異、擷取紀錄」分頁。
- 內容由新到舊排列並分頁載入。
- 擷取紀錄顯示成功、失敗、冷卻原因與各分類批次進度。

## 技術架構

- Python Web：FastAPI、Jinja2、HTMX、SortableJS、Chart.js。
- 資料層：SQLAlchemy、Alembic、SQLite WAL。
- Docker Compose 至少包含 `web`、唯一的 `worker`，以及按需啟動的 `browser-login`。
- `web` 與 `worker` 共用 SQLite、媒體及瀏覽器工作階段掛載目錄。
- Worker 使用 Python Playwright 指定系統 Chromium 可執行檔。
- 所有資料庫時間保存為 UTC；介面與排程以 `Asia/Taipei` 顯示。
- 應用程式只服務單一共享資料空間，不包含註冊、登入或多租戶權限。

## Ubuntu、Tailscale 與 Docker

- 正式目標為 Ubuntu 24.04 LTS ARM64、Docker Engine 與 Docker Compose v2。
- Docker 映像由 ARM64 Ubuntu 主機根據版本化原始碼本機建置。
- Chromium 使用 Ubuntu／Debian ARM64 套件庫提供的系統套件，不依賴預製 Playwright 瀏覽器映像。
- Web 連接埠預設綁定 `100.120.200.116:8080`，以 `.env` 中的 `TAILSCALE_IP` 與連接埠設定覆寫。
- 不得將 Web 或互動式登入服務綁定至 `0.0.0.0`。
- Compose 掛載必須確保容器重啟、重建或版本更新後，SQLite、媒體、瀏覽器工作階段與更新備份仍然存在。

## GitHub 安裝與更新

- 公開儲存庫名稱為 `threads-public-monitor`，採 MIT License。
- Ubuntu 主機使用匿名 HTTPS 從公開 GitHub 儲存庫安裝。
- 正式部署只使用 GitHub Releases 的版本標籤，不追蹤 `main`。
- `install.sh` 驗證 `linux/arm64`、Docker Engine 與 Compose v2，建立 `.env` 及持久化目錄後建置並啟動服務。
- `update.sh` 尋找最新正式 Release、建立 SQLite 備份、切換版本、重建 ARM64 映像、執行資料庫遷移並重新啟動。
- 更新任一步驟失敗時回復原始程式版本與 SQLite 備份。
- 實際 GitHub 使用者或組織名稱在發布前填入；腳本亦可接受明確的公開儲存庫 URL。

## 第一版不包含

- 私人 Threads 帳號擷取。
- 多使用者、應用程式登入、註冊或細分權限。
- 多台 Worker 或多主機水平擴充。
- PostgreSQL、Redis 或外部工作佇列。
- 公開網際網路存取。
- 每日自動備份、異地主機媒體備份或 NAS 同步。
- 為更新互動數字而單獨巡覽所有舊內容。
- 自動處理驗證碼、繞過限制頁或密集並行擷取。
- ARM64 以外架構的正式支援承諾。

## 驗收重點

1. 三種輸入格式都能正規化為同一待驗證帳號，且不產生重複資料。
2. 16 個帳號的排程、續抓位置與卡片順序在容器重啟後仍可恢復。
3. 初始回補、增量擷取、全域節流、每日上限、退避與冷卻都有可見狀態且可測試。
4. 個人檔案版本、統計快照、內容版本、互動快照與疑似移除判定不覆蓋歷史。
5. 相同照片或影片只保存一份，容量與單檔限制會阻止磁碟被填滿。
6. 無登入工作階段、欄位未知、限制頁與解析失敗時，不產生虛假 0 值或錯誤刪除判定。
7. Web 與互動式登入服務只能從設定的 Tailscale IP 存取。
8. Ubuntu 24.04 ARM64 可從正式 GitHub Release 安裝、更新並在失敗時回復。
